# **LANGUAGE FORENSIC ADDENDUM: VB6 — UI BLUEPRINT**
*(Injected into Universal Core V3 at the language_specific_tiers slot)**

---

## **L.1 Form_Load Deep-Scan Mandate**
**MANDATORY:** In VB6, `Form_Load()` is the primary and often only entry point for screen initialization. ALL logic inside `Form_Load()` MUST be fully extracted.

| Init Step | Event | VB6 Literal Source | Business Meaning | Trace ID |
| :--- | :--- | :--- | :--- | :--- |
| e.g., Populate ComboBox | `Form_Load` | `cboStatus.AddItem "Active"` | Pre-loads the valid status values for selection. | TRCE-UI-{artifact_id}-L{line_start} |

**Key VB6-Specific Items to Capture in Form_Load:**
* `ADODCx.RecordSource` assignments — the SQL query that backs a data-bound control.
* `MSFlexGrid` / `ListView` column header initialization — document column order, widths, and alignment.
* Registry reads (`GetSetting()` / `GetPrivateProfileString()`) — identify application configuration loaded at startup.
* API calls (e.g., `GetUserName`, `GetComputerName`) — identify system context captured at open time.
* `Tag` property assignments — VB6 uses `Tag` to carry hidden metadata on controls; extract all assignments.

## **L.2 MDI Parent / Child Relationship**
* **Form Type:** Identify if this form is `MDIForm` (parent), `MDIChild = True` (child), or a standalone `Form`.
* **MDI Child Lifecycle:** Document the `Show` / `Hide` / `Unload` / `MDIForm.ActiveForm` patterns that control this child's visibility from the parent.
* **Inter-Form Communication:** Identify how data is passed between forms (e.g., Public module variables, form properties, `Tag` property, constructor arguments via `Show vbModal`).
* **Instance vs. Singleton:** Document if the form is loaded via `Load frmName` (singleton) or `Dim frm As New frmName` (new instance).

## **L.4 VB6 Error Handling Patterns**
**MANDATORY:** VB6 uses unstructured error handling (`On Error GoTo` / `On Error Resume Next`). Each handler's scope and recovery behavior MUST be documented.

| Procedure | Error Handler Label | Resume Behavior | Captured Err.Number | Business Meaning |
| :--- | :--- | :--- | :--- | :--- |
| [Sub / Function name] | [e.g., `ErrHandler:`, `ExitProc:`) | [e.g., `Resume Next` / `Resume ExitProc` / `GoTo 0`] | [Specific Err.Number values trapped] | [What the error means to the user] |

* **`On Error Resume Next` Scope:** Flag every block where `On Error Resume Next` is active. These are silent failure zones that require explicit error checking in the modern system.
* **`Err.Raise` calls:** Extract custom error numbers raised — these are the domain error vocabulary.

## **L.5 Module-Level Variable Inventory (Form State)**
**MANDATORY:** VB6 forms use module-level variables as their state machine. ALL Private and Public form-level variables MUST be inventoried.

| Variable Name | Type | Scope | Initial Value / Source | Role in Business Logic |
| :--- | :--- | :--- | :--- | :--- |
| `m_bIsNewRecord` | `Boolean` | Private | `False` | Tracks if the current record is being created vs. edited. |

* **Public Variables:** Public form-level variables are accessible from other forms — these are implicit API contracts between screens.
* **Global Module Variables:** Identify all `Public` variables in `.bas` modules — these are the application's global state and must map to modern session/context objects.
