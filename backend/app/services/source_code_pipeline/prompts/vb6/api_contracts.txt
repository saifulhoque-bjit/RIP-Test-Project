## **L.2 Win32 API `Declare Function / Sub` Inventory**
**MANDATORY:** VB6 applications frequently call Win32 API functions via `Declare Function` / `Declare Sub` statements. These are ENTIRELY absent from the standard COM object model and represent hard OS-level dependencies that must be catalogued for modernization. Every `Declare` statement MUST be documented.

| Declare Name | DLL / Library | Alias | Parameter List (Literal) | Return Type | Call Site Event | Business Purpose | Modern Replacement |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `GetUserNameA` | `advapi32.dll` | — | `(lpBuffer As String, nSize As Long) As Long` | `Long` | `Form_Load` | Retrieves the Windows login name of the current user. | `System.Security.Principal.WindowsIdentity.GetCurrent().Name` |
| `ShellExecute` | `shell32.dll` | — | `(hwnd As Long, lpOperation As String, lpFile As String, ...)` | `Long` | `cmdOpenReport_Click` | Opens a file or URL with the default OS application. | `Process.Start()` |

**Key Items to Capture:**
* **`ByVal` vs. `ByRef` Parameters:** In Win32 API calls, the calling convention is exact — `ByVal` vs. `ByRef` on string buffers is critical. Document exactly as declared.
* **String Buffer Patterns:** Identify the `Space(n)` + `Left(result, InStr(result, Chr(0)) - 1)` pattern used to receive strings from Win32 APIs — this is the C-string null-terminator trimming idiom.
* **HWND Handles:** Identify uses of `hWnd` (form handle) passed to Win32 functions — these create OS-level window dependencies.
* **All Declare locations:** `Declare` statements may live in `.bas` Standard Modules (public scope) or Form/Class modules (private scope) — check both.
