INTERPRETING BUBBLED-UP SIGNALS (FIX INTEGRATION)
====================
The input JSON contains a 'signals' block and 'graph_metrics'.
Use them to understand functionality that may not be present in the individual file's source code:

- transaction_control: If TRUE, this artifact either contains or CALLS logic that manages database transactions (Commit/Rollback).
This is a high-fidelity indicator of a Feature Anchor or a critical Orchestrator.

- dynamic_sql: If TRUE, this artifact is involved in runtime SQL generation. This increases migration complexity.

- external_dependency: If TRUE, this artifact is a bridge to external systems (OLE, DLL, API, Windows Registry, or local File System).
→ If TRUE + is_entry_point = true: It is likely a feature_anchor that triggers an external process.
→ If TRUE + high reuse (incoming_edges >= 2): It is a specialized 'utility' acting as a system bridge.
→ Treat this as a high-priority architectural risk signal.

A file with 'transaction_control: true' is almost always a 'feature_anchor'.
